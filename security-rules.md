# Security rules — Orbita

> Governing file. Every change MUST comply with it. Every rule is verifiable.
> Status: Approved 2026-10-30.
> Frame: academic project whose only personal data is the user's location, which is never stored (`DESIGN.md` §7).
> Requirements: RF-07, RF-10, RF-12, RF-16, RNF-03 and RNF-05 of `docs/00-requirements.md`.

## 0. Threat model

No system is 100 % secure. These rules protect what Orbita has, against the attacks that make sense for a public
web page that downloads data from the internet. Each threat points to the rules that cover it.

| Asset | Threat | Example | Rules |
|---|---|---|---|
| User location | Leak | The coordinates end up in a log, a file or a request | SEC-01 to SEC-05, SEC-30 |
| Displayed data | Tampering in transit | Someone on the Wi-Fi changes the CelesTrak response | SEC-26 |
| Displayed data | Malicious or corrupt data | Absurd values, `NaN`, a giant or compressed file, a deeply nested JSON | SEC-10, SEC-27 to SEC-29, SEC-38 |
| Visitor's browser | XSS | A satellite name that contains `<script>` | SEC-13, SEC-32 |
| Logs | Log injection | A downloaded name with line breaks that fakes log lines | SEC-30 |
| Published app | Abuse and denial of service | Many visitors make the app hammer CelesTrak, or send unexpected input | SEC-31, SEC-32 |
| Published app | Information disclosure and CSRF | A traceback that shows paths and code; a forged request | SEC-33 |
| Code and dependencies | Supply chain | A malicious or vulnerable package | SEC-19, SEC-20, SEC-22, SEC-34, SEC-39, SEC-40 |
| Repository | Secret leak or takeover | A key in a commit; someone pushes to `main` with a stolen password | SEC-21, SEC-35 to SEC-37 |

Out of scope: a compromised user computer or browser, a compromise of CelesTrak itself beyond the plausibility
checks of SEC-29, and the infrastructure of the publishing service.

## 1. Personal data: the user's location

The location identifies where a person is. It is read only when the user asks for it, it lives only in memory and
it never leaves the program except to draw the user's own map.

| ID | Rule |
|---|---|
| SEC-01 | The location MUST be read only after the user presses "My location" and accepts the browser permission. It MUST NOT be read automatically when the page opens. The continuous location (P3) MUST be turned on by the user with a visible control and MUST be possible to turn off. |
| SEC-02 | The location MUST live only in `st.session_state` as an `Observer` and be passed as an argument. It MUST NOT be written to disk, to a cache on disk or to any file. `orbita.adapters` MUST NOT import or receive `Observer`: `grep -rn "Observer" src/orbita/adapters/` empty. |
| SEC-03 | The location MUST NOT appear in logs or error messages. `Observer.__repr__` and `Observer.__str__` MUST return `Observer(<hidden>)`, and its fields are named `latitude` and `longitude` so the checklist search finds them. A test runs a live view with an `Observer` and checks that its latitude and longitude do not appear in the captured log (RNF-05). |
| SEC-04 | The location MUST NOT be sent to any external service. The only network host of the program is `celestrak.org` (SEC-15), and no CelesTrak request carries the location. The map requests no tiles from the internet (ADR-002), so no tile provider learns the viewed area. |
| SEC-05 | Next to the "My location" button, the page MUST show the text of the key `location_privacy` from `locales/es.json`, which says that the location is used only to draw the map and the distances and is never stored. On the published version (P3) the text MUST also say that the location travels to the server that runs the page and stays only in its memory. |

## 2. External development services and test data

| ID | Rule |
|---|---|
| SEC-06 | ONLY documentation and code are sent to external development services (including AI assistants). The `.env` file, logs and real locations of people MUST NOT be sent. |
| SEC-07 | Every fixture and example MUST be synthetic, generated by code. Locations in tests MUST be fictional or public reference points (for example, latitude 0 and longitude 0, or a city center), never the home or the real location of a person. Real CelesTrak downloads MUST NOT be versioned as fixtures. |
| SEC-08 | These paths MUST be in `.gitignore`: `.env`, `.venv/`, `__pycache__/`, `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`, `.coverage`, `data/`, `*.log`, `.streamlit/secrets.toml`. |

## 3. Inputs and paths

| ID | Rule |
|---|---|
| SEC-09 | Project configuration files (`locales/es.json`) MUST be read with `json.load` and validated (required keys and types) before use. Invalid file → `ConfigError` with the path and the failing key. |
| SEC-10 | The files downloaded from CelesTrak are untrusted input. A response larger than 5 MB MUST be rejected without reading it whole. It MUST be parsed with `json.loads` and every field used MUST be validated in the domain before use: NORAD number in the list of `DESIGN.md` §3.1, inclination in [0, 180], mean motion in (0, 20], eccentricity in [0, 1), epoch as a valid UTC date no more than 1 day in the future, name as a non-empty `str` of at most 80 characters. Invalid file → `DataValidationError`, the previous file is kept and the error is logged (RF-07). |
| SEC-11 | Every path the program reads or writes MUST be built from `ORBITA_DATA_DIR` or the repo root with a fixed file name from the code (`orbital_elements.json`, `satcat.json`). It MUST NOT derive from downloaded content (for example, a satellite name). |
| SEC-12 | `pickle`, `eval`, `exec`, `yaml.load` and `shell=True` MUST NOT be used in `src/`. |
| SEC-13 | Text that comes from downloaded data (satellite names, owner codes) MUST be shown as plain text. `unsafe_allow_html=True` MUST NOT be used in `src/`, and map tooltips MUST NOT build HTML from downloaded data. |
| SEC-14 | The location delivered by the browser MUST be validated with the domain rule of `DESIGN.md` §4.5 before use; an accuracy that is not a finite number ≥ 0 is ignored. Invalid location → "location unavailable" (RF-12). |

## 4. Database

Not applicable in this project: there is no database and no persistence of user data.

## 5. Network

| ID | Rule |
|---|---|
| SEC-15 | Only `src/orbita/adapters/celestrak_source.py` MUST open network connections and import `httpx`. The base URL is the code constant `https://celestrak.org`. |
| SEC-16 | Every network call MUST use `https://` and a 10 s timeout, MUST NOT be retried (any non-200 response, timeout or connection error ends the attempt, ADR-003), and MUST respect the download intervals of `DESIGN.md` §4.2 (2 h for orbital elements, 24 h for the catalog, counted from the last attempt). |
| SEC-17 | Skyfield MUST use its built-in time data (`load.timescale(builtin=True)`) and MUST NOT download ephemeris or time files at run time. |
| SEC-18 | `.streamlit/config.toml` MUST be versioned with `browser.gatherUsageStats = false` (no usage statistics sent by Streamlit) and, for local development, `server.address = "localhost"` (the page is not reachable from other devices on the same network). The published version (P3) documents its own settings in its ADR. |

## 6. Dependencies and secrets

| ID | Rule |
|---|---|
| SEC-19 | All dependencies MUST be pinned with an exact version (`==`) in `pyproject.toml` and resolved in a versioned `uv.lock`. Installation MUST use the lockfile (`uv sync --locked`). |
| SEC-20 | `uv run pip-audit` MUST run in pre-commit and report no unjustified vulnerabilities (exceptions are documented in `docs/adr/`). |
| SEC-21 | There MUST NOT be secrets in the code or in the repository. The project needs no keys today; if one is ever needed, it lives only in `.env` (local) or in the secrets of the publishing service, and is read only in `orbita.settings`. |
| SEC-22 | Before choosing the browser location component and the map library, their source repository, license, last release date and open security issues MUST be reviewed and recorded in the ADR that chooses them. |

## 7. User honesty

| ID | Rule |
|---|---|
| SEC-23 | The page MUST always show the text of the key `approximate_notice` from `locales/es.json` (positions and distances are approximate and must not be used for space operations), and `README.md` MUST contain the same notice. |
| SEC-24 | Every distance shown MUST carry the sign "≈" (`DESIGN.md` §4.4), and the accuracy reported by the browser MUST be shown next to the user's marker. |
| SEC-25 | With orbital data older than 14 days the page MUST NOT show positions (`DESIGN.md` §4.2, RF-06). |

## 8. Hardening against attacks

### 8.1 Downloaded data

| ID | Rule |
|---|---|
| SEC-26 | `httpx` MUST verify TLS certificates; `verify=False` MUST NOT appear in `src/`. Redirects MUST NOT be followed (`follow_redirects=False`); a redirect response → `DownloadError`. |
| SEC-27 | The 5 MB limit of SEC-10 MUST count the decompressed bytes and be applied while reading in chunks (`iter_bytes`), stopping as soon as it is exceeded, so a small compressed response cannot expand into a huge one. |
| SEC-28 | JSON MUST be parsed with a `parse_constant` that rejects `NaN`, `Infinity` and `-Infinity` (Python's `json` accepts them by default). The top level MUST be a list of at most 50 objects. `ValueError` and `RecursionError` → `DataValidationError`. |
| SEC-29 | Plausibility check: if the mean motion of a satellite differs by more than 5 % from the saved value, the new elements of that satellite are rejected, the previous ones are kept and a `WARNING` with only the NORAD number is logged. |

### 8.2 Logs

| ID | Rule |
|---|---|
| SEC-30 | Text from downloaded data and from the browser MUST NOT be logged. Logs contain only NORAD numbers, counts, sizes in bytes, durations, states and exception types. |

### 8.3 Published app

| ID | Rule |
|---|---|
| SEC-31 | The download intervals are global, not per visitor: the time of the last download is shared by all sessions and protected with a `Lock`. No visitor action can trigger a download outside the intervals of `DESIGN.md` §4.2. |
| SEC-32 | The page MUST NOT accept file uploads or free text: `st.file_uploader`, `st.text_input`, `st.text_area` and `st.chat_input` MUST NOT appear in `src/`. The only controls are buttons, toggles and a selection among the 20 satellites. |
| SEC-33 | `.streamlit/config.toml` MUST NOT disable `server.enableXsrfProtection` or `server.enableCORS`. The published version MUST hide error details from visitors (`client.showErrorDetails` set to its most restrictive value) and show the `unexpected_error` text from `locales/es.json` instead. |

### 8.4 Code, dependencies and repository

| ID | Rule |
|---|---|
| SEC-34 | ruff MUST run with the `S` rules (flake8-bandit, static security analysis). Every `# noqa: S<code>` MUST carry a comment that justifies it. |
| SEC-35 | A secret scanner MUST run in pre-commit and block any commit that contains a secret. The tool (for example, gitleaks) is chosen in an ADR following SEC-22. |
| SEC-36 | GitHub (phase 7): two-factor authentication on the account; `main` protected against force pushes and deletion; Dependabot alerts, secret scanning and push protection enabled. |
| SEC-37 | The repository MUST include `SECURITY.md`, explaining how to report a vulnerability privately (GitHub private vulnerability reporting) and which version is supported. |
| SEC-38 | A malicious input test suite MUST exist and stay green: response larger than 5 MB, compressed response that expands beyond 5 MB, `NaN` and `Infinity`, JSON nested 10 000 levels, name with `<script>`, name with a line break, redirect to another host, mean motion changed by 6 %. Each case ends in `DownloadError`, `DataValidationError` or a rejected satellite, without changing the saved file. |
| SEC-39 | The runtime dependencies are only those of `DESIGN.md` §6. Adding one requires an ADR with the review of SEC-22. |
| SEC-40 | Pre-commit hooks MUST be pinned to an exact version or run through `uv run` with the versions of `uv.lock`. |

## 9. Security review checklist (apply to every implementation)

One box per `SEC-NN` rule, in the same order, with the exact command when there is one.

- [ ] Is the location read only after the button and the permission, and can the continuous location be turned off? (SEC-01)
- [ ] Is the location written anywhere, or does an adapter receive it? `grep -rn "Observer" src/orbita/adapters/` empty (SEC-02)
- [ ] Can the location appear in a log or an error? `Observer` repr test green and `grep -rniE "logger\..*(observer|latitude|longitude)" src/` empty (SEC-03)
- [ ] Is the location sent to any service? Review every network call in the diff (SEC-04)
- [ ] Is the `location_privacy` text shown next to the button? (SEC-05)
- [ ] Were `.env`, logs or real locations attached to an external service during development? (SEC-06)
- [ ] Are fixtures synthetic, with no real locations or real CelesTrak downloads? `git diff --name-only <base> | grep -E "^data/"` empty (SEC-07)
- [ ] Does `.gitignore` contain all the SEC-08 paths? (SEC-08)
- [ ] Is `locales/es.json` read with `json.load` and validated with `ConfigError`? (SEC-09)
- [ ] Is every downloaded field validated in the domain, with the 5 MB limit, before use? (SEC-10)
- [ ] Does any path derive from downloaded content? (SEC-11)
- [ ] Is `pickle`, `eval`, `exec`, `yaml.load` or `shell=True` used? `grep -rnE "pickle|eval\(|exec\(|yaml\.load|shell=True" src/` empty (SEC-12)
- [ ] Is downloaded text shown as plain text? `grep -rn "unsafe_allow_html" src/` empty (SEC-13)
- [ ] Is the browser location validated with rule 4.5 before use? (SEC-14)
- [ ] Any network import outside the CelesTrak adapter? `grep -rlnE "^(import|from) (httpx|requests|urllib)" src/` returns only `celestrak_source.py` (SEC-15)
- [ ] Does every network call use `https://`, a 10 s timeout, no retries and the download intervals counted from the last attempt? (SEC-16)
- [ ] Does Skyfield use `load.timescale(builtin=True)` and download no files? (SEC-17)
- [ ] Does `.streamlit/config.toml` have `gatherUsageStats = false` and `address = "localhost"`? (SEC-18)
- [ ] Versions pinned with `==` and `uv.lock` updated? `uv lock --check` with no errors (SEC-19)
- [ ] `uv run pip-audit` with no unjustified vulnerabilities? (SEC-20)
- [ ] Are there secrets in the diff? `git diff <base> | grep -niE "api[_-]?key|token|secret|password"` reviewed (SEC-21)
- [ ] Was every new third-party component reviewed and recorded in an ADR? (SEC-22)
- [ ] Are `approximate_notice` on the page and the notice in `README.md` present? (SEC-23)
- [ ] Does every distance carry "≈", and is the browser accuracy shown? (SEC-24)
- [ ] Are positions hidden with data older than 14 days? (SEC-25)
- [ ] Is TLS verified and are redirects refused? `grep -rnE "verify=False|follow_redirects=True" src/` empty (SEC-26)
- [ ] Does the 5 MB limit count decompressed bytes while reading in chunks? (SEC-27)
- [ ] Are `NaN` and `Infinity` rejected, with ≤ 50 objects and `RecursionError` handled? (SEC-28)
- [ ] Is a satellite whose mean motion changes more than 5 % rejected? (SEC-29)
- [ ] Is any downloaded or browser text logged? Review every `logger.` in the diff (SEC-30)
- [ ] Is the last download time shared by all sessions under a `Lock`? (SEC-31)
- [ ] Is there any upload or free text control? `grep -rnE "file_uploader|text_input|text_area|chat_input" src/` empty (SEC-32)
- [ ] Are XSRF protection and CORS left on, and error details hidden in the published version? (SEC-33)
- [ ] Does ruff run with `S`, and does every `# noqa: S` carry a justification? `grep -rn "noqa: S" src/` reviewed (SEC-34)
- [ ] Does the secret scanner run in pre-commit? (SEC-35)
- [ ] Are 2FA, `main` protection, Dependabot, secret scanning and push protection on? (SEC-36)
- [ ] Does `SECURITY.md` exist? (SEC-37)
- [ ] Is the malicious input suite green? (SEC-38)
- [ ] Is every runtime dependency in `DESIGN.md` §6 or in an ADR? (SEC-39)
- [ ] Are the pre-commit hooks pinned? (SEC-40)
